# Frontend feature preservation matrix

Audit date: 16 October 2026. This records the inspected baseline, not a claim that the replacement has passed validation. Main baseline: `8c7863e`; unfinished PR #26 head: `c1d6426`. The latter adds three read-only routes, sidebar CSS, tokens and navigation expectations; it does not replace the vacancy workbench JSX. Destination names below refer to the rebuild brief. Final verification belongs in `visual-qa.md` and the delivery report.

## Protected boundaries

The rebuild is `SUPPORTING_IMPLEMENTATION` under [Architecture Guard](../../ARCHITECTURE_GUARD.md). Keep the four independently runnable channels, shared research core, progressive publication, canonical identities, and evidence/QA/workflow separation. A screen does not create a sourcing channel. Search is a stored-record read; it must not invoke research. A saved view or recruiter action must never become research evidence. Closing archives; it does not delete sources, candidates, search logs or reviews.

All live page reads enter through [repository.ts](../../src/lib/data/repository.ts). Browser writes are limited to the three existing `/api/ops/*` endpoints. The ingestion proxy, Edge Function and publisher remain the publication boundary. Demo records must remain explicitly synthetic, and demo mutations remain session-local.

## Existing specification versus implemented capabilities

The interface documents describe broader filters, sort/date/visible-field persistence, a minimised middle pane, exports, and explicit research actions. The production baseline does **not** implement all of them. The static `interface/prototype` is synthetic and is not evidence of supported backend features. Preserve existing working behavior and implement safe local read/filter affordances from loaded records; disable or explain unavailable actions.

Current saved-view runtime keys are only `globalSearch`, `candidateSearch`, `channelFilter`, `regionFilter`, `archiveFilter`, `density`, `marketFilter`, `jobTab`. The JSON schema contains a broader snake-case conceptual contract. Adding frontend-only filters without extending the existing sanitizer would silently drop them on server save; this must be tested before advertising round-trip persistence.

Known absent snapshot fields include target-company rows, detailed QA review rows/history, candidate-claim source URLs/notes, company master identity/industry, vacancy `last_changed`, operation timestamps, and explicit permission roles. These are backend/read-model limitations, not permission to invent values. See [data-contract-map.md](data-contract-map.md).

## Verification handoff

Run `npm run verify` (typecheck, lint, contract scripts, product regression, Vitest, production build). Existing source-text regression scripts name the legacy workspace file and component labels; when extracting components, update checks to follow the real implementation and add behavior-focused cases rather than leaving dead labels or comments to satisfy regexes. Optional legacy smoke scripts are not included in `verify`; record explicitly when they are run.

The browser review must exercise every new action, successful and failed supported mutations, active/closed deep links, candidate assignment isolation, focus/cancel/Escape behavior, and the seven requested viewport widths. Test demo and authorised live reads separately. A demo render does not verify live RLS, authentication, persistence or publication.
