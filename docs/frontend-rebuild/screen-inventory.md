## URL compatibility

| Existing input/link                           | Semantics and limits                                                                                                                                                                      |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/?q=<text>`                                  | First query value only, at most 200 characters; initial vacancy search. Company links depend on this. It is a stored-record filter, not an external search.                               |
| `/?vacancy=<id>`                              | First value only. Must match `Vacancy.id` (database UUID); fallback to default selected row if not found. Closed vacancy deep link expands archive scope to `ALL`.                        |
| `q` plus `vacancy`                            | Filters can hide the requested record; current component follows first visible row. Preserve safe selection and do not claim unsupported guaranteed selection under incompatible filters. |
| `/auth/callback?code=…&next=…`                | `safeNextPath` permits same-origin absolute-path references; rejects external/protocol-relative/backslash/control-character redirects.                                                    |
| `/login?error=missing_code` / `auth_exchange` | Visible auth-recovery messages.                                                                                                                                                           |
| `https://talenttree.co.za`                    | Existing brand link.                                                                                                                                                                      |
| Stakeholder `profileUrl`                      | Current HiringTeam renders external `target="_blank" rel="noreferrer"` profile link.                                                                                                      |
| Source `url`; candidate `profileUrl`          | Read model supports them but current Sources and CandidateCard do not render links. New links must remain evidence-derived.                                                               |

No baseline `candidate`, `tab`, `company`, `stakeholder`, `status`, `returnTo` or persistent URL filter parameters exist. New parameters must have validation and documented fallback behavior; they must not break the two existing vacancy inputs.

## Presentation assets and implementation state

- `src/app/layout.tsx` imports `globals.css`, `shell.css`, and draft `pro-pages.css`; metadata and theme color are shared.
- `tokens.css` defines colors, semantic status mappings, type, surfaces and motion. Legacy comments still refer to the former website design authority; the supplied Pro reference supersedes it for the rebuild.
- `globals.css` owns vacancy panes and many domain styles; `shell.css` owns shared header, login and secondary routes. The draft adds later CSS overrides in `pro-pages.css`, including a 244px sidebar only at >=1280px. This is preliminary adaptation, not an implemented reusable AppSidebar/MobileNav system.
- Current reusable React components are principally `AppHeader` and the monolithic `RecruitmentWorkspace` with private domain components. There is no existing shared Drawer/Button/Card/Search/Badge library.
- Existing public assets are the Talent Tree logo variants and favicon. `design-redesign-preview.png` is a prior screenshot, not evidence that all widths/routes pass.
- `interface/prototype` is a separate buildless synthetic interaction demonstration. It has additional controls and local storage that must not be mistaken for production application capabilities.
